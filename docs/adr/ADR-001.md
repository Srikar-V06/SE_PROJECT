# ADR-001: SQLite as the database
Status: Accepted | Date: 2026-11-19 | Author: BharathVikas-T

## Context
The system needs ACID transactions for double-entry posting and needs to run with
no database server (SRS C-1, NFR-7).

## Decision
Use SQLite 3 with WAL mode, foreign keys, a 5-second busy timeout,
`PRAGMA synchronous=FULL`, and immutability triggers. Apply the required connection
settings whenever a database connection is opened.

## Alternatives considered
- PostgreSQL or MySQL: better concurrent writes, but needs a server and setup.
- In-memory dictionaries: no durability and no transactions.

## Consequences
- Simple setup and easy isolated test databases.
- Only one writer at a time, so financial writes use BEGIN IMMEDIATE (ADR-005).
- In WAL mode, `synchronous=FULL` syncs the WAL at each transaction commit to
  improve durability across power loss; this has a write-performance cost.
- No horizontal scaling (accepted, SRS A-1).
