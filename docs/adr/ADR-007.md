# ADR-007 · Read-only reconciliation on one SQLite snapshot

Proposed for review, 2026-11-28. Records the implementation merged in PR #50.
Requirements FR-5.1 through FR-5.6. Related notes [[sqlite-acid-wal]] and
[[ai-session-phase5-reconciliation-ui]].

## Decision

The ADMIN endpoint opens a connection, executes BEGIN and reads transactions,
wallets, treasuries and ordered ledger entries inside that read transaction.
The first read establishes the SQLite snapshot. Independent autocommit reads
could mix balances from before a transfer with entries from after it.

After closing the connection, compute signed sums with Python integers. Check
transaction balance by currency, cached balances against account postings, and
the currency totals including the treasury. Verify the ordered chain using
ADR-009. Return PASS or FAIL with counts, failing identifiers and UTC time.
Reconciliation does not repair records.

## Consequences and evidence

WAL permits a writer to commit while the reader retains its snapshot. Holding
the rows in memory costs space proportional to ledger size. The 10,000-entry
timing target needs a benchmark. The reconciliation suite commits a transfer
between report reads and checks the snapshot counts. Corrupted database copies
exercise both mismatch and broken-chain reporting.
